У тебе типова ситуація після міграції або часткової локалізації БД 👍
Потрібно:

* 🔹 **прибрати `@tott_10` тільки для об'єктів схеми `tsk`**
* 🔹 **залишити `@tott_10` для інших схем (bsk, інші)**
* 🔹 об'єктів багато → вручну нереально

Нижче — системний підхід.

---

# ✅ Найбезпечніший спосіб — через REGEXP replace

Тобі потрібно замінити тільки конструкції виду:

```
tsk.nameobj@tott_10
```

на

```
tsk.nameobj
```

Але НЕ чіпати:

```
bsk.nameobj@tott_10
other.name@tott_10
```

---

## 🔹 1. Якщо це SQL-файли (експорт APEX / дамп)

### Варіант через VS Code / Notepad++ / будь-який редактор з regex

### 🔎 Знайти:

```
\btsk\.([a-zA-Z0-9_]+)@tott_10\b
```

### 🔁 Замінити на:

```
tsk.\1
```

---

### ✔ Що робить regex:

| Частина           | Значення                         |
| ----------------- | -------------------------------- |
| `\b`              | межа слова                       |
| `tsk\.`           | тільки схема tsk                 |
| `([a-zA-Z0-9_]+)` | ім'я будь-якого об'єкта          |
| `@tott_10`        | саме цей dblink                  |
| `\1`              | повертає захоплену назву об'єкта |

---

## 🔹 2. Якщо це вже всередині APEX (views, processes, regions)

Можеш виконати SQL по APEX metadata.

### 🔎 Знайти всі згадки:

```sql
SELECT application_id,
       page_id,
       region_name,
       source
FROM apex_application_page_regions
WHERE LOWER(source) LIKE '%tsk.%@tott_10%';
```

---

# 🔥 3. Автоматичне оновлення через SQL

Можна масово оновити через regexp_replace.

### Приклад:

```sql
UPDATE apex_application_page_regions
SET source = REGEXP_REPLACE(
                source,
                '\btsk\.([a-zA-Z0-9_]+)@tott_10\b',
                'tsk.\1'
             )
WHERE REGEXP_LIKE(source, '\btsk\.([a-zA-Z0-9_]+)@tott_10\b');
```

---

⚠ Перед виконанням:

```
BEGIN
  apex_application_install.generate_offset;
END;
/
```

і обов'язково зробити export backup.

---

# 🔹 4. Альтернативно — створити synonym

Якщо tsk тепер локальна схема, можна зробити:

```sql
CREATE SYNONYM tsk.nameobj FOR tsk.nameobj@tott_10;
```

але:

❌ це не вирішує проблему
❌ створювати сотні synonym — погана практика
❌ з часом буде плутанина

# 🏆 Найкраща стратегія

| Сценарій               | Рішення                             |
| ---------------------- | ----------------------------------- |
| Є SQL-файл             | regex replace в редакторі           |
| Уже імпортовано в APEX | масовий update через REGEXP_REPLACE |
| Хочеш контроль         | зробити спочатку SELECT preview     |

# 🧠 Якщо хочеш ще безпечніше

Можемо зробити replace тільки там, де:

* JOIN
* UPDATE
* INSERT INTO

Щоб не зачепити текст у HTML або коментарях.
