Оце дуже правильний момент ⚠
Тут головне — не зламати логіку `ac.unit_id`.

Твоя базова умова зараз:

```sql
AND (ac.unit_id IS NULL OR ac.unit_id = uc.unit_id)
```

Вона означає:

> Access Control дозволяє або всі unit (NULL), або конкретний unit користувача.

---

# 🎯 Тобі треба:

✔ якщо shift_unit НЕ вибраний → працює стара логіка
✔ якщо shift_unit вибраний → дозволити доступ і по ньому
✔ але не зламати обмеження ac.unit_id

---

# ✅ Правильне доповнення

Ось безпечний варіант:

```sql
AND (
       ac.unit_id IS NULL
    OR ac.unit_id = uc.unit_id
    OR (
           uc.shift_unit IS NOT NULL
       AND ac.unit_id = uc.shift_unit
       )
)
```

---

# 🔎 Що це означає

1️⃣ Якщо в access_control unit не обмежений → пускаємо
2️⃣ Якщо співпадає з базовим uc.unit_id → пускаємо
3️⃣ Якщо користувач вибрав shift і access_control дозволяє цей unit → пускаємо

---

# ❗ Чого НЕ можна робити

❌ НЕ можна писати так:

```sql
OR uc.shift_unit IS NOT NULL
```

Бо це повністю зніме обмеження.

❌ НЕ можна просто замінити uc.unit_id на shift_unit
Бо тоді ти зламаєш access_level 2.

---

# 🧠 Логічна схема

Було:

```
ac.unit_id → перевіряємо проти uc.unit_id
```

Стає:

```
ac.unit_id → перевіряємо проти
   - uc.unit_id
   - shift_unit (якщо є)
```

---

# 🏆 Найчистіший варіант (якщо shift з WITH)

У WITH:

```sql
:P0_SHIFT_UNIT AS shift_unit
```

І в WHERE:

```sql
AND (
       ac.unit_id IS NULL
    OR ac.unit_id = uc.unit_id
    OR (uc.shift_unit IS NOT NULL AND ac.unit_id = uc.shift_unit)
)
```

---

# 💬 Важливе питання

Shift має:

* 🔹 повністю заміняти unit?
* 🔹 чи просто додавати ще один допустимий unit?

З того що ти описуєш —
правильніше другий варіант (override, а не заміна).

---

Якщо хочеш — можу переписати повністю твій level 2 блок акуратно зі всіма дужками, бо там зараз є небезпечна зона з OR EXISTS, яка може давати неочікувані результати.
