Тут проблема саме у виклику з JavaScript. Ваш PL/SQL уже **віддає готовий PDF у HTTP response**, а `apex.server.process()` у стандартному режимі розрахований передусім на JSON/text-відповіді. Ось це:

```javascript
dataType: "blob"
```

для `apex.server.process()` — не той механізм, на який варто покладатися. Через це `blobData` у `success` не обов'язково є справжнім `Blob`, придатним для `URL.createObjectURL()`.

У вашій ситуації я б спочатку спробував мінімальну зміну — передати `responseType: "blob"` через `xhrFields`:

```javascript
apex.server.process(
    "DOWNLOAD_PDF_REPORT",
    {},
    {
        xhrFields: {
            responseType: "blob"
        },

        success: function (blobData) {

            console.log(blobData);
            console.log(blobData instanceof Blob);

            const blobUrl = URL.createObjectURL(blobData);

            const link = document.createElement("a");
            link.href = blobUrl;
            link.download = "Список завдань.pdf";

            document.body.appendChild(link);
            link.click();
            link.remove();

            URL.revokeObjectURL(blobUrl);
        },

        error: function (xhr, status, error) {
            console.error(
                "Помилка завантаження:",
                status,
                error
            );

            apex.message.alert(
                "Не вдалося завантажити файл."
            );
        }
    }
);
```

Тобто **прибрати**:

```javascript
dataType: "blob"
```

і замість нього:

```javascript
xhrFields: {
    responseType: "blob"
}
```

У DevTools перевірте:

```javascript
console.log(blobData instanceof Blob);
```

має бути:

```text
true
```

А також:

```javascript
console.log(blobData.type);
```

очікувано:

```text
application/pdf
```

Але у вашому PL/SQL я бачу ще одну проблему: ви одночасно вручну формуєте HTTP headers:

```plsql
sys.htp.init;
sys.owa_util.mime_header('application/pdf', false, 'UTF-8');
sys.htp.p(
    'Content-Length: ' ||
    sys.dbms_lob.getlength(l_export.content_blob)
);
sys.owa_util.http_header_close;
```

а потім викликаєте:

```plsql

    p_export => l_export
);
```

`APEX_DATA_EXPORT.DOWNLOAD` **сам формує response для завантаження**. Я б не змішував ці два механізми.

Тобто спочатку спробуйте значно простіше:

### Але є ще простіший і надійніший спосіб

Для **завантаження файлів я взагалі не став би використовувати AJAX**.

Причина проста: AJAX добре підходить для:

```text
браузер → сервер → JSON → браузер
```

а файл природно працює як:

```text
браузер → URL → HTTP response → attachment
```

Тобто ваш PL/SQL process із:

```plsql
apex_data_export.download(...)
```

краще запускати **звичайним HTTP request**, а не `apex.server.process()`.

Наприклад, зробити Page Process:

```text
Name:
DOWNLOAD_PDF_REPORT

Processing Point:
Before Header

Server-side Condition:
Request = DOWNLOAD_PDF
```

І ваша кастомна кнопка:

```javascript
const url = apex.util.makeApplicationUrl({
    pageId: 15,
    request: "DOWNLOAD_PDF"
});

window.location.href = url;
```

У процесі:

```plsql
apex_data_export.download(
    p_export => l_export
);
```

Браузер побачить:

```http
Content-Type: application/pdf
Content-Disposition: attachment; ...
```

і сам завантажить файл.

При цьому сторінка **не повинна перейти на PDF**, тому що відповідь має `Content-Disposition: attachment`.

Це позбавляє вас від усього цього:

```javascript
Blob
URL.createObjectURL
document.createElement("a")
link.click()
URL.revokeObjectURL
```

Для вашого кейсу я б обрав саме цей варіант. У вас PDF уже нормально формується в PL/SQL; зараз ви просто намагаєтесь протягнути binary response через AJAX, хоча для завантаження файлу це не потрібно.
