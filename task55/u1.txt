Так, це вже можна нормально закласти в структуру звіту.

`P11_UNIT` я б використав у двох місцях: по-перше, для вибору відповідної кількості людей із `u1_people / u2_people / u3_people`; по-друге, для формування тексту заголовка звіту. Логіка може бути така:

```sql
CASE TO_NUMBER(NVL(:P11_UNIT, '1'))
    WHEN 1 THEN NVL(t.u1_people, 0)
    WHEN 2 THEN NVL(t.u2_people, 0)
    WHEN 0 THEN NVL(t.u3_people, 0)
END AS people_count
```

Для самого заголовка звіту можна завести hidden item, наприклад `P11_REPORT_TITLE`, і перед refresh IR заповнювати його залежно від `P11_UNIT`:

```plsql
:P11_REPORT_TITLE :=
    CASE :P11_UNIT
        WHEN '1' THEN 'Назва для unit 1'
        WHEN '2' THEN 'Назва для unit 2'
        WHEN '0' THEN 'Назва для unit 0'
    END;
```

А в Region Title:

```text
&P11_REPORT_TITLE.
```

Щодо колонок — так, я б робив саме **дві групи по 4 колонки**:

```text
                         НАРЯДИ
        13:00       21:00       06:00       Примітка

                    РОЗПОРЯДЖЕННЯ
        13:00       21:00       06:00       Примітка
```

Тобто фінальна структура:

| Підрозділи | Наряди |       |       |          | Розпорядження |       |       |          |
| ---------- | -----: | ----: | ----: | -------- | ------------: | ----: | ----: | -------- |
|            |  13:00 | 21:00 | 06:00 | Примітка |         13:00 | 21:00 | 06:00 | Примітка |

Тут є важливий нюанс саме з **Interactive Report і Excel export**. У IR звичайні колонки мають один header row. Тобто справжній дворівневий заголовок типу `Наряди` над чотирма колонками та `Розпорядження` над іншими чотирма штатно зробити складніше, ніж у Interactive Grid.

Якщо критично, щоб це було видно і **в експорті Excel**, я б не покладався лише на CSS/JavaScript-групування заголовків у браузері, бо це оформлення зазвичай не переноситься в XLSX.

Найнадійніший варіант для експорту — зробити назви самих колонок однозначними:

```text
Наряди — 13:00
Наряди — 21:00
Наряди — 06:00
Наряди — Примітка

Розпорядження — 13:00
Розпорядження — 21:00
Розпорядження — 06:00
Розпорядження — Примітка
```

Тоді навіть у Excel структура буде абсолютно зрозумілою.

На екрані ж можемо додатково візуально зробити групи `Наряди` та `Розпорядження`, але це вже буде presentation layer.

Щодо Highlight Interactive Report — так, це для твого випадку хороший вибір. Якщо колір повинен потрапляти в export, краще використовувати саме штатний `Highlight`, а не кастомний CSS. Тоді я б у SQL залишив службову колонку, наприклад:

```sql
CASE
    WHEN department_name = 'Всього'
        THEN 'TOTAL'
    WHEN department_name = 'Кількість працюючих'
        THEN 'WORKERS_TOTAL'
    ELSE
        'DEPARTMENT'
END AS row_type
```

І вже в Interactive Report створив Highlight rules:

```text
ROW_TYPE = DEPARTMENT
→ світло-бежевий фон

ROW_TYPE = TOTAL
→ окреме оформлення

ROW_TYPE = WORKERS_TOTAL
→ жирне / інший фон
```

Причому `ROW_TYPE` можна приховати від користувача.

Є ще одна тонкість: ти раніше казав, що бежевим має бути саме **колонка «Підрозділи»**, а не весь рядок. У стандартному IR Highlight можна налаштовувати як `Row` або `Cell`. Для цього випадку треба робити **Cell Highlight саме для `DEPARTMENT_NAME`**, а умову прив'язувати до `ROW_TYPE = 'DEPARTMENT'`. Тоді і візуально буде правильно, і експорт матиме більше шансів зберегти оформлення.

У SQL я б тепер замінив старий блок вибору unit на:

```sql
CASE NVL(:P11_UNIT, '1')
    WHEN '1' THEN NVL(t.u1_people, 0)
    WHEN '2' THEN NVL(t.u2_people, 0)
    WHEN '0' THEN NVL(t.u3_people, 0)
    ELSE 0
END AS people_count
```

А назви колонок у IR поставив би так:

```text
DEPARTMENT_NAME → Підрозділи

OUTFIT_13        → Наряди — 13:00
OUTFIT_21        → Наряди — 21:00
OUTFIT_06        → Наряди — 06:00
OUTFIT_NOTE      → Наряди — Примітка

ORDER_13         → Розпорядження — 13:00
ORDER_21         → Розпорядження — 21:00
ORDER_06         → Розпорядження — 06:00
ORDER_NOTE       → Розпорядження — Примітка
```

Саме так я б будував першу робочу версію: вона збереже **Interactive Report, стандартний Excel export, P11_UNIT, підсумкові рядки та Highlight** без надто крихких JS-рішень.

А вже після цього можемо окремо зробити візуальний дворівневий header `Наряди / Розпорядження` над IR, не ламаючи експорт.
