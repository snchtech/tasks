Так, тепер зрозумів, про що ти. Ти маєш на увазі **Column Grouping / групування колонок на рівні налаштувань Interactive Report для експорту**, а не візуальний дворівневий header у браузері.

Тоді це якраз підходить дуже добре. Структуру можна залишити такою:

```text
Підрозділи

Група "Наряди":
    13:00
    21:00
    06:00
    Примітка

Група "Розпорядження":
    13:00
    21:00
    06:00
    Примітка
```

У самому IR на сторінці користувач бачитиме звичайні колонки:

```text
Підрозділи | 13:00 | 21:00 | 06:00 | Примітка | 13:00 | 21:00 | 06:00 | Примітка
```

а при експорті в Excel вони будуть логічно згруповані:

```text
                НАРЯДИ                          РОЗПОРЯДЖЕННЯ
        13:00  21:00  06:00  Примітка     13:00  21:00  06:00  Примітка
```

Тобто в цьому випадку **не потрібно** називати колонки `Наряди — 13:00`, `Розпорядження — 13:00` і т. д. Краще залишити короткі заголовки `13:00`, `21:00`, `06:00`, `Примітка`, а приналежність визначати через групу колонок.

Для SQL відповідно залишаємо aliases:

```sql
department_name,

outfit_13,
outfit_21,
outfit_06,
outfit_note,

order_13,
order_21,
order_06,
order_note,

row_type
```

А в APEX налаштовуємо:

```text
OUTFIT_13
OUTFIT_21
OUTFIT_06
OUTFIT_NOTE
    → Group = Наряди

ORDER_13
ORDER_21
ORDER_06
ORDER_NOTE
    → Group = Розпорядження
```

Це навіть краще для твоєї задачі, бо SQL взагалі не повинен знати про оформлення груп.

І з Highlight теж погоджуюсь: якщо ти плануєш штатний **Highlight Interactive Report**, тоді `ROW_STYLE` нам фактично вже не потрібен як CSS-клас. Краще перейменувати його концептуально у `ROW_TYPE` і використовувати як службове поле:

```sql
'DETAIL' AS row_type
```

для звичайних рядків,

```sql
'TOTAL' AS row_type
```

для `Всього`,

і

```sql
'WORKERS_TOTAL' AS row_type
```

для `Кількість працюючих`.

Потім `ROW_TYPE` приховуємо у звіті та використовуємо в Highlight.

Тому я б у фінальному SQL уже відразу врахував три речі: **`P11_UNIT`**, `ROW_TYPE` для Highlight і структуру з 8 колонками, готову під дві export-групи `Наряди` / `Розпорядження`.

Єдине, що треба ще уточнити перед тим, як я дам тобі вже остаточний SQL без умовних місць: які саме три значення `P11_UNIT` і які їм відповідають назви заголовка звіту. Наприклад, якщо `1 = ...`, `2 = ...`, `0 = ...`, дай мені ці три назви — і я відразу вставлю їх у готове рішення.
