Рішення з **кнопками ↑ ↓** для ієрархічних підзавдань у вашій моделі (APEX_COLLECTION) — це на практиці **найстабільніший варіант** для Oracle APEX. Воно простіше за drag, не конфліктує з IG refresh і добре працює з ієрархією.

Нижче повна схема.

---

# 1. Логіка сортування

У вас є структура:

| поле   | значення      |
| ------ | ------------- |
| SEQ_ID | id рядка      |
| C005   | parent_id     |
| C006   | subtask_order |

Сортування повинно працювати **тільки всередині одного parent**.

### Приклад

```
Task
  1 A
  2 B
  3 C
```

Move up:

```
B ↑
```

результат

```
B
A
C
```

---

### Для дочірніх

```
A
  A1
  A2
  A3
```

```
A3 ↑
```

результат

```
A
  A1
  A3
  A2
```

# 2. Додаємо кнопки у SQL

У ваш SELECT додайте дві колонки.

```sql
CASE
WHEN subtask_order > 1
THEN
'<button class="move-up" data-id="'||seq_id||'" data-parent="'||parent_seq_id||'">↑</button>'
END move_up,
```

```sql
CASE
WHEN 1=1
THEN
'<button class="move-down" data-id="'||seq_id||'" data-parent="'||parent_seq_id||'">↓</button>'
END move_down
```

# 5. Ajax Process

Назва:

```
MOVE_SUBTASK
```

---

### PL/SQL

```plsql
DECLARE

    l_id NUMBER:=apex_application.g_x01;
    l_parent NUMBER:=apex_application.g_x02;
    l_dir VARCHAR2(10):=apex_application.g_x03;

    l_order NUMBER;
    l_swap_id NUMBER;
    l_swap_order NUMBER;

BEGIN

-- поточний порядок
SELECT TO_NUMBER(c006)
INTO l_order
FROM apex_collections
WHERE collection_name='TASK_SUBTASKS_COLLECTION'
AND seq_id=l_id;

IF l_dir='UP' THEN

    SELECT seq_id, TO_NUMBER(c006)
    INTO l_swap_id, l_swap_order
    FROM (
        SELECT seq_id,c006
        FROM apex_collections
        WHERE collection_name='TASK_SUBTASKS_COLLECTION'
        AND NVL(c005,-1)=NVL(l_parent,-1)
        AND TO_NUMBER(c006)<l_order
        ORDER BY TO_NUMBER(c006) DESC
    )
    WHERE ROWNUM=1;

ELSIF l_dir='DOWN' THEN

    SELECT seq_id, TO_NUMBER(c006)
    INTO l_swap_id, l_swap_order
    FROM (
        SELECT seq_id,c006
        FROM apex_collections
        WHERE collection_name='TASK_SUBTASKS_COLLECTION'
        AND NVL(c005,-1)=NVL(l_parent,-1)
        AND TO_NUMBER(c006)>l_order
        ORDER BY TO_NUMBER(c006)
    )
    WHERE ROWNUM=1;

END IF;

-- swap
apex_collection.update_member_attribute(
p_collection_name=>'TASK_SUBTASKS_COLLECTION',
p_seq=>l_id,
p_attr_number=>6,
p_attr_value=>l_swap_order
);

apex_collection.update_member_attribute(
p_collection_name=>'TASK_SUBTASKS_COLLECTION',
p_seq=>l_swap_id,
p_attr_number=>6,
p_attr_value=>l_order
);

END;
```

# 6. Що відбувається

Алгоритм:

1. визначаємо `subtask_order`
2. шукаємо **сусідній запис того ж parent**
3. **міняємо order місцями**

---

# 7. Переваги

✔ працює з **ієрархією**
✔ **батьківські рухаються між батьківськими**
✔ **дочірні тільки у свого parent**
✔ працює з **collections**
✔ не потребує drag library
✔ не ламає Interactive Grid
